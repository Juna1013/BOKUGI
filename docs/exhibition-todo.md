## ゴール

最優先で完成させる体験は、次の一連の流れです。

```text
待機デモ → 新しい紙で描く → 完成する → QRで持ち帰る
                                      └→ 明示的に同意した作品だけ会場へ展示する
```

通常の描画体験を壊さず、展示端末では説明なしでも開始・終了・次の来場者への引き継ぎができることを完了条件とします。

### 展示MVPの完了条件

- [ ] 初見の来場者が、説明なしで描画開始からQR保存まで完了できる
- [ ] キーボード表示、端末回転、リサイズで作品が消えない
- [ ] 前の来場者の作品・作者名・掲載設定が次のセッションへ残らない
- [ ] 通信切断時も共有シートまたはPNG保存へフォールバックできる
- [ ] WebGPUとCPUフォールバックの両方で主動線が完走する
- [ ] 完成・アップロード・自動リセットが重なっても、別セッションの結果が表示されない

## 1. 展示仕様とデータ方針（S-00）

- [x] 展示モードの起動方法を決める
  - 通常モードを維持し、`?mode=exhibition`で展示モードを有効化する。
  - 受入条件：展示モードの有無をコード変更なしで切り替えられる。
- [x] 展示セッションの時間を決める
  - 描画時間に上限は設けない。描画中は90秒無操作で15秒警告し、操作すれば継続する。
  - 完成・QR画面は90秒無操作で15秒警告する。
  - 受入条件：QRを読み取っている最中に作品が突然消えず、次の来場者の操作で安全に新規開始できる。
- [x] 一時画像の保存先と公開方式を決める
  - Cloudflareを第一候補とし、Workers Static Assets + Worker + private R2 + D1で構成する。
  - 2日間の技術検証に失敗した場合はVercelへ切り替える。
  - 受入条件：PNGのアップロード、取得、自動期限切れを実機で確認できる。
- [x] データ保持期間を決める
  - QR受け取りは24時間、ギャラリー表示はイベント終了までとする。
  - Workerで期限切れアクセスを拒否し、CronとR2 Lifecycleで物理削除する。
- [x] 同意とプライバシーの文言を決める
  - QR受け取りと「会場ギャラリーへ飾る」は別操作にし、掲載は既定OFFにする。
  - 掲載同意後はスタッフ承認を挟まず即時掲載することを明示する。
  - 作者名・落款・画像の保存範囲、保持期限、削除方法を画面内に短く表示する。
  - 受入条件：作品を持ち帰るだけなら、ギャラリーへ公開されない。
- [x] 通信障害時の挙動を決める
  - QR生成に失敗しても、既存の共有シートとPNG保存を利用できるようにする。

## 2. 作品・セッションデータの保持（S-01）

現状は [`src/main.ts`](../src/main.ts) の `resize` で `solver.resize()` と `history.clear()` を呼ぶため、作者名入力時のソフトウェアキーボードや端末回転で作品が消える可能性があります。

- [ ] 表示領域の変化と、物理グリッドを作り直す必要があるリサイズを分離する
- [ ] 共有ダイアログ表示中のソフトウェアキーボード開閉では、シミュレーションを初期化しない
- [ ] 端末回転・実ウィンドウサイズ変更時の保持方式を実装する
  - 候補：既存グリッドの再サンプリング、またはスナップショットを新グリッドへ復元する。
- [ ] リサイズ後もUndo/Redoの扱いが破綻しないよう仕様を決める
- [ ] WebGPUからのreadback中、入力中、カード生成中の競合を防ぐ
- [x] カード再生成時のスナップショット寿命を修正する
  - 現状の [`src/export/ShareCardController.ts`](../src/export/ShareCardController.ts) は初回生成後の後始末で `artwork` も破棄するため、構図や作者名を変更しても再生成できない。
  - プレビューURLの解放と作品スナップショットの破棄を分離する。
  - 受入条件：初回表示後に構図・作者名を変更すると、プレビューと保存PNGの両方へ反映される。
- [ ] 展示モードでは作者情報をセッション限定にする
  - 現状の作者名は `localStorage` に残るため、通常モードの保存動作と展示モードの一時利用を分ける。
  - 受入条件：新しい紙を開始した時点で、前の来場者の作者名・落款・掲載同意が復元されない。
- [x] セッション終了時にプレビュー用Object URL、生成済み`File`、アップロード状態を破棄する
  - 現時点ではアップロード状態は未実装。`resetSession()`をQR実装時の破棄境界として利用する。
- [ ] 次のケースを自動または手動テストに残す
  - [ ] 作者名入力欄をフォーカスしても作品が消えない
  - [ ] ダイアログを開閉しても作品が変化しない
  - [ ] 縦横回転後も作品が保持される
  - [ ] WebGPUとCPUフォールバックで同じ結果になる

## 3. 展示モードと自動リセット（S-02）

- [ ] 展示セッションを状態機械として実装する

  ```text
  idle → drawing → finishing → delivery → resetting → idle
  ```

- [ ] リセット処理を一か所へ集約する
  - 対象：流体状態、GPU状態、履歴、入力・Pointer Capture、水洗い、選択中の筆と色、完成ダイアログ、作者情報、掲載同意、QR、待機デモ。
  - リセット完了までは新しい入力を受け付けない。
- [ ] 入力の有効化・無効化、ストローク開始・終了、リセットをコントローラーから扱えるAPIに整理する
- [ ] 非同期処理へセッションIDを持たせ、古いカード生成・アップロード結果を次のセッションへ反映しない
- [ ] 待機デモを実装する
  - 無操作時に墨のにじみや代表的な筆致を自動表示する。
  - 来場者が触れた瞬間にデモ用状態を破棄し、その入力を最初の一筆として白紙から開始する。
  - デモ操作をUndo履歴や来場者作品へ混ぜない。
- [ ] 最初の有効な入力で `idle` から `drawing` へ遷移する
- [ ] 描画中の操作を無操作タイマーへ反映する
- [ ] 完成後のカード生成・QR表示中は自動リセットを止める、または十分な猶予とカウントダウンを表示する
- [ ] 「次の作品を始める」を用意し、確認後にグリッド・履歴・作者情報のセッション状態を初期化する
- [ ] スタッフ向けの即時リセット操作を用意する
- [ ] 通常モードでは待機デモ・無操作リセットが動かないことを確認する
- [ ] `prefers-reduced-motion` 有効時は、待機デモを静的な案内へ切り替える

## 5. QRで作品を持ち帰る（S-04）

- [ ] 既存の作品カード生成結果（PNG `File`）を、共有・保存・QRへ渡せる共通の受け渡しAPIに整理する
- [ ] 一時アップロードAPIを実装する
  - 入力：PNG、必要最小限のメタデータ。
  - 出力：推測困難な作品ID、HTTPS URL、`expiresAt`。
  - 画像形式・容量・寸法をサーバー側で検証する。
  - ストレージの秘密鍵をブラウザへ置かず、レート制限と冪等性を持たせる。
- [ ] ストレージのTTL削除を設定し、期限切れ後に取得できないことを確認する
- [ ] ダウンロードページを実装する
  - 作品プレビュー、保存操作、期限表示を含める。
  - URLだけ知っている第三者へ、作者名以外の個人情報を返さない。
- [ ] QRコードを生成し、完成ダイアログへ表示する
  - QRには画像本体ではなく短いHTTPS URLを入れる。
  - 作品URLを第三者のQR生成サービスへ送らず、アプリ内で生成する。
  - 画面輝度・表示サイズ・余白を含め、iOS/Androidの標準カメラで読み取れることを確認する。
- [ ] 「アップロード中」「準備完了」「失敗」「期限切れ」を明示する
- [ ] 失敗時に再試行、共有シート、PNG保存を選べるようにする
- [ ] 二重タップや再試行で同じ作品が大量生成されないよう、多重送信を防ぐ
- [ ] QR受け取りだけではギャラリーへ掲載されないことをE2Eテストする
